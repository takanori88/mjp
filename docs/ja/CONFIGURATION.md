# 設定

[English](../en/CONFIGURATION.md) · [README](README.md#設定)

## ファイルの場所と読み込み

`~/.config/mjp/config.toml` を作ると、プレビューを設定できます。場所は `$HOME/.config/mjp/config.toml` に固定し、`XDG_CONFIG_HOME` は使いません。XDG の設定仕様には準拠しません。同じ `HOME` ならターミナルと Finder 起動で同じ場所を参照できます。ターミナルで `HOME` を変更すると別の場所を読みます。`HOME` が未設定、空、相対パスなら警告なしで設定を無効にします。

各 GUI プロセスは最初のウィンドウを作る前に1回だけ読み込みます。文書、stdin、Welcome、ファイルを開けない場合の案内と、Finder の要求などで同じプロセスに後から追加するウィンドウに適用します。変更が効くのは新しいプロセスからです。変更後の設定を使うには、受け取り先のアプリを終了してから起動し直してください。設定 UI や実行中の切り替え操作はありません。

2026-11-06 に持ち主が Issue #37 のスライス1〜4の実機確認項目を確認済みです。テーマの表示と OS の外観変更への追従、Finder 起動、寸法、配置とカスケード、常に手前に表示する場合の操作を含みます。[Issue #37 の確認記録](https://github.com/takanori88/mjp/issues/37)を参照してください。設定の読み込みが起動時間に与える影響は、対象の Mac で未測定です。

## 警告と既定値

設定は64 KiB以下の通常の UTF-8 TOML ファイルとし、通常ファイルへのシンボリックリンクはたどります。ファイルがない場合は警告せず、`config.toml` 自体のリンク切れを検出した場合は警告します。読み込み失敗や、`01`・重複キーなどを含む不正な TOML は、すべての設定を既定値に戻し、ウィンドウ内に警告を表示します。

不正な項目は後述の既定値を使い、他の正しい設定は維持します。未知のトップレベル項目は警告します。`window` がテーブル以外なら、警告1件と既定のウィンドウ設定を使います。`window` 直下の未知のキーは各1件、未知の入れ子のテーブルは中身を調べず1件の警告にします。

警告は自動更新の警告を先に、同じバナーに最大3件、1件200文字（省略時の `…` を含む）まで表示し、省略件数を付けます。読み込みエラーの間はエラーを優先し、回復後に警告を再表示します。

## テーマ設定

```toml
theme = "dark"
```

`"light"` または `"dark"` で表示を固定します。`"system"`、`theme` の省略、設定ファイルなしの場合は、実行中の変更も含めて OS の表示に従います。値は大文字・小文字を区別します。`theme` の不正値は `"system"` に戻します。CLI の `--theme` オプションはありません。

## ウィンドウサイズ設定

初期表示のコンテンツ領域の幅・高さを片方だけ、または両方指定できます。

```toml
[window]
width = 1000
height = 700
```

単位は論理ピクセル（macOS ではポイント）で、タイトルバーは含みません。後述の位置を設定しなければ中央に開き、未指定または不正な幅は800、高さは600を使います。値は ASCII の数字だけで書く `1`〜`4294967295` の整数とします。符号（`+1000`）、区切り（`1_000`）、基数の接頭辞（`0x3e8`）、浮動小数点、文字列は、その項目を警告して無視し、他方の寸法とテーマは維持します。

有効な寸法を明示すると、Tauri による主ディスプレイの作業領域への初期サイズ調整を有効にします。実際のコンテンツ寸法は OS とディスプレイに制約されるため、タイトルバー全体が収まる保証はありません。有効な寸法の明示指定がなければ、従来どおり800×600を使います。手動リサイズや別ディスプレイへの移動時には再調整しません。

## ウィンドウ位置設定

主ディスプレイの作業領域（メニューバーと Dock を除いた範囲）の右上にプレビューを開けます。寸法も指定する場合は、同じ `[window]` テーブルにまとめてください。

```toml
[window]
position = "top-right"
margin_x = 16
margin_y = 16
```

`margin_x` は右端から、`margin_y` は上端からの距離で、単位は論理ピクセル（macOS のポイント）です。各既定値は16で、ASCII の数字だけで書く `0`〜`4294967295` の整数を受け付けます。不正な余白は項目ごとに警告1件を出して16を使います。`position` なしの正しい余白は警告なしで受け付け、位置には影響しません。位置は大文字・小文字を区別する文字列 `"top-right"` だけに対応します。省略時はずらさず中央に開き、不正な位置も警告付きで同じ扱いにします。主ディスプレイを取得できない場合は、警告なしで中央に開き、寸法の設定は維持します。

同じプロセスで続けて開くウィンドウは、左下へ24ポイントずつずらします。この量は固定です。作業領域に収まる位置の数で巡回するため、表示位置が重なる場合があります。閉じたウィンドウの破棄後は、空いたうちの最小のカスケード slot を再利用します。手動で移動しても slot は変わりません。Welcome とファイルを開けない場合の案内も同じ規則です。Welcome が slot 0 を占有している間は最初の文書が slot 1 を使い、その文書ウィンドウの生成成功後に Welcome を閉じます。開いている文書の再要求は前面に出すだけです。別の CLI 起動を含め、異なるプロセスの間では位置を調整しません。

作業領域はウィンドウを作るたびに取得します。収まることを優先して余白を減らし、コンテンツ寸法が作業領域より大きい軸は左端または上端にそろえます。寸法を明示した場合は、前述の初期サイズ調整も使います。位置は外枠の左上に合わせますが、下端の計算にはタイトルバーを含めないため、外枠の下端がその高さ分だけ出る場合があります。倍率が異なるディスプレイと左右の Dock は、対象の Mac で未確認です。

## 常に手前に表示する設定

通常のデスクトップの Space で、他のアプリをアクティブにしても、プレビューを通常のウィンドウより手前に表示できます。

```toml
[window]
always_on_top = true
```

寸法や位置を指定している場合は、同じ `[window]` テーブルに追加してください。TOML の真偽値 `true` と `false` だけを受け付けます。省略または `false` なら、従来どおり通常のウィンドウになります。`"true"`、`1`、`[]` など他の型は警告1件と `false` にし、正しいテーマ・寸法・位置は維持します。この設定は大きさと配置には影響しません。

別の Space や全画面アプリの上への表示、同じ層かそれ以上の層にあるウィンドウ（他のアプリの「常に手前」のウィンドウを含む）より手前への表示は保証しません。mjp のウィンドウは同じ層にあり、普通に重なり合います。重なり順を開いた順やカスケード slot の順に固定しません。2026-11-06 に、Chrome を全画面にした Space では mjp が隠れることを持ち主が確認しています。

## 全項目入りの設定例

ウィンドウ設定は1つの `[window]` テーブルにまとめます。

```toml
theme = "dark"

[window]
width = 1000
height = 700
position = "top-right"
margin_x = 16
margin_y = 16
always_on_top = true
```
